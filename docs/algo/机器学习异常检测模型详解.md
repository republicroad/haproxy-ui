## 一、引言

### 1.1 为什么需要机器学习

传统WAF依赖**签名规则**（正则表达式匹配已知攻击特征），存在三大局限性：
1. **零日攻击**：无法检测未知攻击模式
2. **规避技术**：攻击者可混淆/编码载荷绕过静态规则
3. **维护成本**：规则库需要人工持续更新

机器学习模型通过学习**正常流量模式**，识别偏离基线的**异常行为**。

### 1.2 两类检测范式

| 范式 | 原理 | 模型 |
|------|------|------|
| **监督学习** | 用标记数据训练分类器 | Random Forest、SVM |
| **无监督学习** | 从数据中发现异常 | Isolation Forest、Autoencoder |

## 二、Random Forest（随机森林）分类

### 2.1 原理概述

**随机森林**是集成学习方法，通过构建多个决策树并综合投票得出结果。

```
输入特征
   │
   ├──→ 决策树1 ──→ 结果1
   ├──→ 决策树2 ──→ 结果2
   ├──→ 决策树3 ──→ 结果3
   │        ...
   └──→ 决策树N ──→ 结果N
              │
              └──→ 多数投票/平均 ──→ 最终预测
```

### 2.2 决策树基础

**决策树**通过一系列判断规则将数据分类：

```
请求数据
  │
  ├─ URL长度 > 100 ? 
  │     ├─ 否 → 继续判断
  │     └─ 是 → 是否包含UNION？
  │           ├─ 是 → 判定SQLi
  │           └─ 否 → 继续
  │
  ├─ 参数包含<script> ?
  │     ├─ 是 → 判定XSS
  │     └─ 否 → 继续
  │
  └─ ... → 判定正常
```

### 2.3 随机森林核心机制

#### 为什么叫"随机"？
- **样本随机**：每棵树用随机子集训练（Bootstrap抽样）
- **特征随机**：每次分裂只考虑随机特征子集

#### 为什么有效？
- **降低方差**：多树平均减少单树过拟合
- **抗噪声**：单棵树出错不影响整体
- **处理高维**：特征子集避免维数灾难

### 2.4 WAF中的特征提取

用于分类的攻击特征：

| 特征类别 | 具体特征 | 说明 |
|---------|---------|------|
| **URL特征** | URL长度 | 长URL可能包含攻击载荷 |
| | 特殊字符数 | `'`、`"`、`<`、`>`等 |
| | 编码字符数 | `%`、`\\x`等编码 |
| **参数特征** | 参数长度分布 | 异常长度 |
| | 参数熵 | 高熵=可疑 |
| | 类型混淆 | 应为数字却是字符串 |
| **头部特征** | User-Agent异常 | 扫描器UA |
| | Referer缺失 | 直接访问 |
| | Cookie完整性 | 缺失/异常 |
| **请求特征** | 请求方法 | 异常方法 |
| | 内容类型 | 不匹配 |
| | 请求频率 | 突发请求 |

### 2.5 实战案例：IntelliWAF的Random Forest

**应用场景**：WAF第4层，分类已知攻击

#### 数据结构
```
训练样本：CSIC 2010 HTTP数据集（61,065条）
特征维度：约30个HTTP请求特征
分类目标：normal / sqli / xss / path_traversal / ssrf / cmdi
```

#### 参数调优指南

| 参数 | 默认值 | 作用 | 调优建议 |
|------|--------|------|---------|
| `n_estimators` | 100 | 决策树数量 | 增加可提升精度但增加开销，200-500常用 |
| `max_depth` | None | 树最大深度 | 限制可防过拟合，10-20 |
| `min_samples_split` | 2 | 叶子最小样本 | 增大减少过拟合 |
| `max_features` | sqrt | 每棵树特征数 | 分类用sqrt，回归用N/3 |
| `class_weight` | None | 类别权重 | 处理不平衡数据（攻击远少于正常） |

### 2.6 优缺点

**优点**
- ✅ 精度高，抗过拟合
- ✅ 处理高维、非线性数据
- ✅ 特征重要性可解释
- ✅ 并行训练，速度快

**缺点**
- ❌ 需要标注数据（监督学习）
- ❌ 无法检测训练集外的未知攻击
- ❌ 模型较大，推理有一定延迟

## 三、Isolation Forest（孤立森林）

### 3.1 核心思想

**"异常是容易被孤立的数据点"**——异常数据少且特征不同，只需少量随机切分就能隔离。

### 3.2 与Random Forest的本质区别

| 维度 | Random Forest | Isolation Forest |
|------|---------------|-----------------|
| **任务** | 分类（已知类别） | 异常检测（未知异常） |
| **训练** | 需要标注 | 无需标注（无监督） |
| **目标** | 找决策边界 | 找易隔离点 | 
| **输出** | 类别/概率 | 异常分数 |

### 3.3 算法原理

#### 关键概念：隔离（Isolation）

```
正常数据点分布密集 → 需要多次切分才能隔离
异常数据点分布稀疏 → 少量切分即可隔离
```

```
① 正常数据（密集分布）
    ┌──────────────────────┐
    │   ●  ●  ●  ●  ●     │
    │  ●  ●  ●  ●  ●  ●   │
    │   ●  ●  ●  ●  ●     │
    └──────────────────────┘
    需要多次切分才能隔离单个点

② 异常数据（稀疏分布）
    ┌──────────────────────┐
    │  ●  ●  ●  ●          │
    │  ●  ●  ●       ●     │ ← 异常点，一次切分即可隔离
    │  ●  ●  ●  ●          │
    └──────────────────────┘
    异常点很快被孤立
```

#### 构造孤立的树（iTree）

```
输入：样本子集 + 特征子集
输出：一棵二叉搜索树

1. 随机选一个特征
2. 随机选一个该特征的切分值
3. 数据按切分值分成左右子树
4. 递归直到：
   - 数据只有一个点
   - 达到最大深度
   - 所有数据相同
```

```
特征1 = URL长度
      │
      ├─ 长度 < 50 ──→ 正常分支
      └─ 长度 > 50 ──→ 
             │
             ├─ 特征2 = 特殊字符数
                    │
                    ├─ < 3 ──→ 正常
                    └─ > 3 ──→ ● 异常点（深度=2，很短）
```

异常点深度浅（少次切分就隔离），正常点深度深。

### 3.4 异常分数计算

给定数据点x，异常分数：

```
score(x) = 2^(- E(h(x)) / c(n) )

其中：
- E(h(x)) = 所有树中x的路径长度平均值
- c(n)    = 平均路径长度（n为样本数）
- n       = 样本数量

c(n) = 2H(n-1) - (2(n-1)/n)

判断标准：
- score接近1  → 异常（路径很短）
- score接近0  → 正常（路径很长）  
- score≈0.5  → 无明显异常
```

### 3.5 实现示例

```python
from sklearn.ensemble import IsolationForest
import numpy as np

# 1. 准备数据（无需标注！）
# 只使用正常流量特征作为输入
X_train = extract_features(all_requests)  # [n_samples, n_features]

# 2. 训练模型
model = IsolationForest(
    n_estimators=100,          # 树的棵树
    contamination=0.01,        # 预期异常比例（1%）
    max_samples=256,           # 每棵树的最大样本数
    max_features=1.0,          # 每棵树使用全部特征
    bootstrap=False,           # 是否自助抽样
    random_state=42
)
model.fit(X_train)

# 3. 预测（返回1=正常, -1=异常）
predictions = model.predict(X_test)

# 4. 获取异常分数
scores = model.decision_function(X_test)
# 分数越低越异常

# 5. 应用示例
for i, score in enumerate(scores):
    if score < -0.5:  # 异常阈值
        print(f"请求 {i}: 异常，分数={score}")

### 使用增量学习（生产环境）
# sklearn的IsolationForest不支持在线更新
# 需要定期批量重训练，或使用River等在线学习库
```

### 3.6 关键参数

| 参数 | 作用 | 调优建议 |
|------|------|---------|
| `n_estimators` | 树的数量 | 100-200，越多越稳定 |
| `contamination` | 预估异常比例 | 关键参数！WAF通常0.001-0.01 |
| `max_samples` | 每棵树的样本数 | 256-1024，小提升速度 |
| `max_features` | 特征维度 | 默认1.0全量 |

**⚠️ contamination是核心参数**：
- 设太大→误报多（把正常流量当攻击）
- 设太小→漏报多（放过真实攻击）

### 3.7 优缺点

**优点**
- ✅ 无需标注数据（无监督）
- ✅ 检测未知攻击（零日攻击）
- ✅ 线性时间复杂度，适合流式数据
- ✅ 内存占用低

**缺点**
- ❌ 对contamination参数敏感
- ❌ 无法给出攻击类型（只能判异常/正常）
- ❌ 高维数据效果下降（特征需筛选）

## 四、LSTM（长短期记忆网络）

### 4.1 为什么需要LSTM

**WAF中的序列问题**：攻击往往表现为**一系列行为的累积**，而非单个请求。

```
正常用户行为序列：
登录页面 → 首页 → 商品列表 → 商品详情 → 下单
         ↕ 行为路径有节奏

攻击者行为序列：
登录页面 → 暴力尝试(×1000) → 注入尝试 → 逃逸
         ↕ 行为路径异常/重复/跳跃
```

传统模型（RF/IF）无法捕捉**时间顺序**和**上下文依赖**，LSTM专为此设计。

### 4.2 RNN与LSTM基础

#### RNN（循环神经网络）
```
标准RNN：存在梯度消失问题，难以学习长序列
```

#### LSTM的三大门控
LSTM通过三个"门"控制信息流，解决长序列记忆问题：

```
         ┌─────────────────────────────┐
输入x₁ ──→│         LSTM单元            │──→ 输出h₁
         │  ┌───────────────────────┐  │
         │  │  遗忘门     输入门    │  │
         │  │  (f_t)      (i_t)     │  │
         │  │    ↓          ↓       │  │
         │  │  细胞状态 ←→ 更新     │  │
         │  │    ↓          ↓       │  │
         │  │        输出门 (o_t)   │  │
         │  └───────────────────────┘  │
         └─────────────────────────────┘
```

| 门 | 作用 | 公式 |
|----|------|------|
| **遗忘门** | 决定丢弃哪些旧信息 | `f_t = σ(W_f · [h_{t-1}, x_t] + b_f)` |
| **输入门** | 决定存入哪些新信息 | `i_t = σ(W_i · [h_{t-1}, x_t] + b_i)` |
| **输出门** | 决定输出哪些信息 | `o_t = σ(W_o · [h_{t-1}, x_t] + b_o)` |

### 4.3 WAF中的LSTM架构

#### 输入构造：行为会话特征序列

```
每个时间步t的特征向量x_t：
[请求路径, 请求方法, 参数个数, 响应码, 时延, 是否包含特殊字符, ...]

会话 = x_1, x_2, x_3, ..., x_T
```

#### 网络架构

```
输入序列 (T个时间步，每步d维特征)
    │
    ▼
┌──────────────────────────────┐
│       LSTM层 (隐藏单元=128)    │
└──────────────────────────────┘
    │
    ▼
┌──────────────────────────────┐
│       LSTM层 (隐藏单元=64)     │
└──────────────────────────────┘
    │
    ▼
┌──────────────────────────────┐
│       全连接层 + Dropout      │
└──────────────────────────────┘
    │
    ▼
Sigmoid输出 → 异常概率 (0-1)
```

#### 实现示例

```python
import torch
import torch.nn as nn
import torch.optim as optim

class BehaviorLSTM(nn.Module):
    def __init__(self, input_dim, hidden_dim, num_layers=2):
        super().__init__()
        self.lstm = nn.LSTM(
            input_size=input_dim,
            hidden_size=hidden_dim,
            num_layers=num_layers,
            batch_first=True,
            dropout=0.2
        )
        self.fc = nn.Sequential(
            nn.Linear(hidden_dim, 64),
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(64, 1),
            nn.Sigmoid()
        )
    
    def forward(self, x):
        # x: (batch, seq_len, input_dim)
        out, (h_n, c_n) = self.lstm(x)
        # 取最后一个时间步
        last_out = out[:, -1, :]
        return self.fc(last_out)

# 生成会话序列
def build_session_sequences(logs, max_len=50):
    """
    将日志按会话分组，每个会话变成特征序列
    """
    sessions = group_by_session(logs)  # 按IP+Cookie+时间聚合
    sequences = []
    for session in sessions:
        features = []
        for log in session:
            features.append(extract_features(log))
        # 填充/截断到固定长度
        if len(features) < max_len:
            features += [[0]*len(features[0])] * (max_len - len(features))
        sequences.append(features[:max_len])
    return torch.tensor(sequences, dtype=torch.float32)

# 训练
model = BehaviorLSTM(input_dim=20, hidden_dim=128)
optimizer = optim.Adam(model.parameters(), lr=0.001)
criterion = nn.BCELoss()

for epoch in range(50):
    for batch_x, batch_y in dataloader:
        pred = model(batch_x).squeeze()
        loss = criterion(pred, batch_y)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
```

### 4.4 优缺点

**优点**
- ✅ 捕捉时间序列和上下文依赖
- ✅ 检测慢速、分布式攻击（如低慢速DDoS）
- ✅ 处理变长序列

**缺点**
- ❌ 训练数据需标注（监督学习）
- ❌ 训练慢，计算开销大
- ❌ 需要长时间序列数据形成基线
- ❌ 黑盒模型，可解释性差

## 五、Transformer（注意力机制）

### 5.1 原理概述

**Transformer**完全抛弃RNN的顺序处理，改用**自注意力机制（Self-Attention）**并行处理整个序列，捕捉长距离依赖。

### 5.2 自注意力机制

核心问题：序列中每个元素与哪些其他元素最相关？

```
请求："/login?user=admin' OR '1'='1"
                  ↑          ↑
                   这两个token高度相关
                   （SQL注入特征）
```

#### QKV机制

```
每个token生成三个向量：
- Query (Q)：我要找什么
- Key (K)：我能提供什么
- Value (V)：我实际的内容

注意力权重 = softmax(Q·K^T / √d)

注意力输出 = Σ(注意力权重 × V)
```

#### 多头注意力

```
多个QKV并行 → 每个头关注不同方面
头1: 关注语法模式
头2: 关注敏感关键词
头3: 关注编码混淆
```

### 5.3 WAF中的Transformer

#### 输入形式

```
请求序列token化：
["/login", "?", "user", "=", "admin'", "OR", "'1'='1", ...]
```

或使用**请求嵌入**（embedding）

#### 架构（可以更轻量）

```
输入序列
    │
    ▼
Token Embedding + 位置编码
    │
    ▼
┌──────────────────────────┐
│    Multi-Head Attention   │
└──────────────────────────┘
    │
    ▼
┌──────────────────────────┐
│    前馈神经网络 (FFN)      │
└──────────────────────────┘
    │   (可堆叠N层)
    ▼
池化 (CLS token / 平均池化)
    │
    ▼
分类头 → 异常/类别预测
```

### 5.4 实现示例（轻量版）

```python
import torch
import torch.nn as nn
from torch.nn import MultiheadAttention

class LightweightWAFTransformer(nn.Module):
    def __init__(self, vocab_size, d_model=64, nhead=4, num_layers=3):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, d_model)
        self.positional = nn.Parameter(torch.randn(1, 128, d_model))
        
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model,
            nhead=nhead,
            dim_feedforward=256,
            dropout=0.1,
            batch_first=True
        )
        self.encoder = nn.TransformerEncoder(encoder_layer, num_layers)
        self.classifier = nn.Linear(d_model, 1)
        self.sigmoid = nn.Sigmoid()
    
    def forward(self, x):
        # x: (batch, seq_len) token IDs
        emb = self.embedding(x) + self.positional[:, :x.size(1), :]
        out = self.encoder(emb)
        out = out.mean(dim=1)  # 平均池化
        return self.sigmoid(self.classifier(out))

# 请求token化
def tokenize_request(request):
    tokens = []
    for part in request['url'].split('/'):
        tokens.extend(tokenize_word(part))
    for key, value in request['params'].items():
        tokens.extend(tokenize_param(key, value))
    return tokens
```

#### 位置编码（关键差异）
Transformer无序，必须加入位置信息：
```python
# 正弦位置编码
def positional_encoding(seq_len, d_model):
    pe = torch.zeros(seq_len, d_model)
    for pos in range(seq_len):
        for i in range(0, d_model, 2):
            pe[pos, i] = sin(pos / 10000 ** (i / d_model))
            pe[pos, i+1] = cos(pos / 10000 ** (i / d_model))
    return pe
```

### 5.5 优缺点

**优点**
- ✅ 捕捉长距离依赖（比LSTM更优）
- ✅ 并行计算（比LSTM快）
- ✅ 全局上下文理解
- ✅ 预训练模型可迁移

**缺点**
- ❌ 模型大，推理开销高
- ❌ 小样本效果不如传统模型
- ❌ 训练成本高（需GPU）
- ❌ 不适合资源受限的WAF场景

## 六、Autoencoder（自编码器）

### 6.1 原理

**只学正常样本的重构**——异常样本没法被正常模型重构好，重构误差大即判异常。

```
输入 ──→ 编码器(压缩) ──→ 潜在表示 ──→ 解码器(还原) ──→ 输出
 x      [x → z]            z        [z → x']           x'

目标：最小化 ‖x - x'‖（重构误差）

正常请求：重构误差小
异常请求：重构误差大
```

### 6.2 实现示例

```python
import torch
import torch.nn as nn

class WAFAnomalyAutoencoder(nn.Module):
    def __init__(self, input_dim, hidden_dim=32):
        super().__init__()
        # 编码器：降维
        self.encoder = nn.Sequential(
            nn.Linear(input_dim, 64),
            nn.ReLU(),
            nn.Linear(64, hidden_dim),   # 压缩到32维
            nn.ReLU()
        )
        # 解码器：还原
        self.decoder = nn.Sequential(
            nn.Linear(hidden_dim, 64),
            nn.ReLU(),
            nn.Linear(64, input_dim),
            nn.Sigmoid()  # 若特征归一化到[0,1]
        )
    
    def forward(self, x):
        z = self.encoder(x)
        return self.decoder(z)

# 训练：只用正常请求
model = WAFAnomalyAutoencoder(input_dim=50)
criterion = nn.MSELoss()

for epoch in range(100):
    for batch in normal_data_loader:
        recon = model(batch)
        loss = criterion(recon, batch)  # 重构误差
        loss.backward()

# 推理：计算重构误差
def is_anomaly(x, model, threshold=0.1):
    recon = model(x.unsqueeze(0))
    error = nn.functional.mse_loss(recon, x.unsqueeze(0)).item()
    return error > threshold, error
```

### 6.3 优缺点

**优点**
- ✅ 无监督（只需正常数据）
- ✅ 检测未知攻击
- ✅ 模型轻量

**缺点**
- ❌ 阈值（threshold）难调
- ❌ 假设"正常=好重构"，可能被对抗攻击骗
- ❌ 正常模式变化大时误报多

## 七、模型对比与选型

### 7.1 核心对比

| 属性 | Random Forest | Isolation Forest | LSTM | Transformer | Autoencoder |
|------|--------------|------------------|------|-------------|-------------|
| **学习类型** | 监督 | 无监督 | 监督 | 监督/自监督 | 无监督 |
| **是否需要标注** | ✅是 | ❌否 | ✅是 | ✅是 | ❌否 |
| **检测未知攻击** | ❌ | ✅ | ❌ | ✅(可微调) | ✅ |
| **序列/上下文** | ❌ | ❌ | ✅强 | ✅最强 | ❌ |
| **可解释性** | 特征重要性 | 低 | 低 | 低 | 低 |
| **训练速度** | 快 | 快 | 慢 | 慢 | 中 |
| **推理速度** | 快 | 快 | 中 | 中慢 | 快 |
| **内存/模型大小** | 中 | 小 | 大 | 大 | 小 |
| **训练数据量** | 中 | 少 | 多 | 很多 | 中 |
| **适用WAF层** | 已知攻击分类 | 未知攻击检测 | 会话行为 | 复杂语义 | 异常检测 |

### 7.2 选择决策树

```
你的WAF场景是？
│
├─ 有标注数据，要分类已知攻击？
│     ├─ 特征多、数据量大 → Random Forest
│     └─ 需要捕捉行为序列 → LSTM / Transformer
│
├─ 无标注数据，要检测未知攻击？
│     ├─ 检测单个请求异常 → Isolation Forest
│     └─ 学习正常样本模式 → Autoencoder
│
├─ 处理请求语义，理解混淆攻击？
│     └─ 有算力 → Transformer / LLM(WAF)
│
└─ 资源受限（边缘/嵌入式）？
      └─ Isolation Forest（最轻量）
```

### 7.3 推荐组合（分层防御）

实践中**不只用单一模型**，而是组合使用：

```
请求入口
   │
   ▼
┌──────────────────────┐
│ Layer 1: RF分类       │ ← 快速拦截已知攻击
│ (已知类型的高精度分类)  │    低延迟，可解释
└──────────────────────┘
   │ (未命中)
   ▼
┌──────────────────────┐
│ Layer 2: IF孤立森林    │ ← 检测未知/变种攻击
│ (无监督异常检测)       │    不需要标注
└──────────────────────┘
   │ (异常但低置信)
   ▼
┌──────────────────────┐
│ Layer 3: LSTM/Transformer│ ← 深层次序列与语义分析
│ (行为序列建模)         │    慢路径，高精度
└──────────────────────┘
   │
   ▼
决策：阻断 / 放行 / 挑战 / 限速
```

### 7.4 性能优化建议

```
1. 特征筛选（降维）
   - 用RF feature_importance去掉无关特征
   - 减少维度 → Isolation Forest效果更好

2. 模型量化
   - PyTorch: torch.quantization
   - 减少模型大小，提升推理速度

3. 模型蒸馏
   - 用大模型(Transformer)训练，蒸馏到小模型(RF)
   - 兼顾精度与效率

4. 异步流水线
   - 快路径同步（RF/IF）
   - 慢路径异步（LSTM/Transformer，不阻塞请求）
```

### 8.1 部署架构

```
                    ┌──────────────┐
客户端 ──→ ──→ ──→ │    WAF网关    │
                    └──────────────┘
                          │
                ┌─────────┼─────────┐
                ▼         ▼         ▼
         ┌──────────┐┌──────────┐┌──────────┐
         │ Model A  ││ Model B  ││ Model C  │
         │  (RF)    ││  (IF)    ││  (LSTM)  │
         └──────────┘└──────────┘└──────────┘
                │         │         │
                └─── 结果聚合 + 评分 ───┘
                          │
                          ▼
                  阻断/放行/挑战/限速
```

### 8.2 MLOps流程

```
① 数据采集
   实时流量 → 特征仓库(Feature Store)
   
② 模型训练
   定期重训练（每天/每周）
   评估指标：准确率、误报率、漏报率

③ 模型评估
   影子部署（shadow deployment）
   ── 与线上模型并行，只记录不拦截
   
④ 灰度发布
   小比例流量 → 全量
   
⑤ 线上监控
   ├─ 误报率监控（关键指标）
   ├─ 延迟监控（P99 < 50ms）
   ├─ 漂移检测（PSI/KL散度）
   └─ 自动回滚（误报突增→回退旧模型）
   
⑥ 反馈闭环
   安全分析师的判定 → 回流训练集 → 重新训练
```

### 8.3 关键运维指标

| 指标 | 目标 | 说明 |
|------|------|------|
| **精确率(Precision)** | >95% | 拦截中真攻击比例（低误报） |
| **召回率(Recall)** | >90% | 真攻击中被拦截比例（低漏报） |
| **F1分数** | >0.92 | 精度与召回平衡 |
| **P99延迟** | <50ms | 99%请求的检测延迟 |
| **误报率** | <1% | 正常流量被误判比例 |
| **模型漂移** | PSI<0.2 | 输入分布变化检测 |
