## 一、核心概念

### 1.1 什么是行为基线

**行为基线**是应用在"正常状态"下的流量特征统计画像。它描述了两个问题：

1. **正常流量长什么样？**（均值、分布、模式）
2. **正常流量的波动范围有多大？**（方差、标准差）

### 1.2 为什么要建立基线

```
静态阈值的问题：
  "请求数>100/分钟 → 封禁"  ← 静态阈值

  慢速API：平时30次/分钟（永远达不到100）
  高流量API：平时500次/分钟（100次可能是异常低值）

结论：固定阈值无法适配不同应用

行为基线：
  用μ(均值) ± k·σ(标准差) 动态判断
  无论应用流量大小，都能自适应判断异常
```

### 1.3 基线的核心度量

| 度量 | 符号 | 含义 | 用途 |
|------|------|------|------|
| **均值** | μ | 正常水平 | 期望值 |
| **标准差** | σ | 波动程度 | 容忍范围 |
| **Z-score** | z | 偏离程度 | 异常判定 |
| **分位数** | p50/p95/p99 | 分布位置 | 边缘异常 |
| **熵值** | H | 多样性 | 扫描器检测 |

### 1.4 Z-score核心公式

```
z = (x - μ) / σ

z的含义：
  z=0   → 完全正常（等于均值）
  |z|<1 → 正常波动（1σ内，约68%数据）
  |z|<2 → 轻度偏离（2σ内，约95%数据）
  |z|≥2 → 显著偏离（超出95%置信区间）→ 通常触发告警
  |z|≥3 → 严重偏离（超出99.7%）→ 高危

基础判定规则：
  |z| ≥ 2.0 → ANOMALY
  |z| ≥ 3.0 → CRITICAL
```

## Step 0：准备工作

### 0.1 明确目标

**回答以下问题：**
- 要检测哪些攻击类型？（SQLi / XSS / 暴力破解 / 爬虫 / 慢速DDoS）
- 在哪个层级检测？（单请求 / 单IP / 单会话 / 全网）
- 实时性要求？（秒级告警 / 分钟级分析）
- 可接受的误报率？（误报过多会浪费运营人力）

### 0.2 确定检测维度

| 维度 | 说明 | 示例 |
|------|------|------|
| **时间窗口** | 聚合多长时间的数据 | 1分钟 / 5分钟 / 1小时 |
| **聚合粒度** | 按什么单位聚合 | 单IP / 单用户 / 单路径 / 全局 |
| **流量粒度** | 分析哪层流量 | 请求 / 响应 / 会话 |

### 0.3 划分学习窗口

```
建议：7天为一轮典型学习周期
  - 覆盖工作日/周末流量差异
  - 覆盖日间/夜间流量差异
  - 观察业务高峰/低谷

窗口选择：
  短期(7天)  → 快速反应，但易受一次性活动干扰
  中期(14天) → 平衡及时性与稳定性
  长期(30天) → 稳定，但反应慢

说明：可从7天起步，效果稳定后拉长
```

### 0.4 准备数据标签

```
行为基线阶段通常需要标注哪些是"正常"流量：

✅ 正常：业务流量、人工访问、已知爬虫(搜索引擎)
⚠️ 待定：灰度上线、促销活动、外部API调用
❌ 异常：封禁IP、已知攻击、渗透测试

关键：学习窗口内的数据应尽量"纯净"（无攻击干扰）
```

## Step 1：特征收集与定义

### 1.1 特征分层

```
特征从低到高分为多个层级，各自独立建立基线：

L1 单请求级（微特征）
  - URL路径、参数、头部、时长

L2 聚合级（中特征）
  - 请求速率、错误率、URI熵（按IP/路径聚合）

L3 会话级（宏特征）
  - 会话路径、停留时长、点击序列

L4 全网级（全局特征）
  - 总QPS、带宽、连接数
```

### 1.2 推荐特征清单

#### A. 速率类（最常见）

| 特征 | 说明 | 检测目标 |
|------|------|---------|
| 请求速率 | 每分钟请求数(按IP) | 暴力破解、DDoS |
| 新建连接速率 | 每秒新TCP连接 | SYN洪泛 |
| 失败登录速率 | 登录失败/分钟 | 撞库攻击 |
| 401/403错误率 | 错误响应比例 | 扫描、爆破 |

#### B. 内容/分布类

| 特征 | 说明 | 检测目标 |
|------|------|---------|
| 参数长度分布 | 参数值长度均值/方差 | 载荷注入 |
| 参数熵值 | 字符分布的熵 | 高熵=可疑载荷 |
| 特殊字符密度 | `'`、`"`、`<`密度 | SQLi/XSS |
| 请求体大小 | POST体长度 | 超大载荷 |
| 响应大小 | 响应体长度分布 | 数据泄露/错误 |

#### C. 结构类

| 特征 | 说明 | 检测目标 |
|------|------|---------|
| URI熵值 | URI路径多样性 | 目录扫描 |
| 会话路径长度 | 导航深度 | 爬虫遍历 |
| 命中404比例 | 不存在路径比例 | 扫描器 |
| UA多样性 | User-Agent分布 | bot伪装 |

### 1.3 特征选择原则

```
✅ 应选特征：
  - 与攻击行为强相关
  - 业务上可解释
  - 数值稳定（波动可度量）

❌ 应避免特征：
  - 攻击行为无关（如浏览器版本）
  - 数值过大波动（峰值难捕捉）
  - 无法稳定获取（如JS渲染数据）
```

### 3.3 特征计算与聚合

#### 按时间窗口聚合

```python
import pandas as pd
from collections import defaultdict

def aggregate_features(logs, window_sec=60):
    """
    将原始请求按 (ip, 时间窗口) 聚合成特征。
    每个 (ip, 窗口) 是一行特征。
    """
    groups = defaultdict(list)
    for log in logs:
        window = (log['timestamp'] // window_sec) * window_sec
        key = (log['client_ip'], window)
        groups[key].append(log)
    
    features = []
    for (ip, window), reqs in groups.items():
        features.append({
            'ip': ip,
            'window_start': window,
            # 速率
            'request_count': len(reqs),
            'request_rate': len(reqs) / window_sec,
            # 错误率
            'error_rate_4xx': sum(1 for r in reqs if r['status'] >= 400) / len(reqs),
            'error_rate_5xx': sum(1 for r in reqs if r['status'] >= 500) / len(reqs),
            # 时长
            'avg_response_time': sum(r['response_time_ms'] for r in reqs) / len(reqs),
            'p99_response_time': percentile([r['response_time_ms'] for r in reqs], 99),
            # 结构
            'uri_entropy': compute_entropy([r['path'] for r in reqs]),
            'unique_uris': len(set(r['path'] for r in reqs)),
            # 参数
            'avg_param_len': avg([len(str(p)) for r in reqs for p in r['params'].values()]),
            'special_char_ratio': avg([count_special(r) for r in reqs]),
        })
    return pd.DataFrame(features)
```

### 3.4 分布形态检查

**不同特征服从不同分布，需针对处理：**

```python
import numpy as np
from scipy import stats

def check_distribution(values, feature_name):
    """
    检查特征是否近似高斯分布。
    若严重偏斜，做对数/Box-Cox变换。
    """
    # 偏度和峰度
    skewness = stats.skew(values)
    kurtosis = stats.kurtosis(values)
    
    print(f"{feature_name}: 偏度={skewness:.2f}, 峰度={kurtosis:.2f}")
    
    if abs(skewness) > 1:
        # 严重偏斜 → 对数变换
        transformed = np.log1p(values)  # log(1+x) 处理0值
        print(f"  → 使用对数变换")
        return transformed
    return values

# 典型特征分布
# request_rate: 偏度大（幂律）→ 对数变换
# error_rate: 0-1区间 → Beta分布
# uri_entropy: 近似正态 → 直接用
# response_time: 正偏态 → 对数变换
```

```python
def time_split(df, train_ratio=0.7, val_ratio=0.2):
    df = df.sort_values('window_start')  # 按时间排序
    n = len(df)
    train_end = int(n * train_ratio)
    val_end = int(n * (train_ratio + val_ratio))
    return df.iloc[:train_end], df.iloc[train_end:val_end], df.iloc[val_end:]
```

### 4.2 各特征基线计算方法

#### （1）速率类：均值±标准差

```python
import numpy as np

def compute_rate_baseline(feature_values):
    """
    适用：request_rate, conn_rate等速率特征
    """
    # 先做对数变换处理偏斜
    log_values = np.log1p(feature_values)
    
    mu = np.mean(log_values)
    sigma = np.std(log_values)
    
    return {
        "mean": mu,
        "std": sigma,
        "distribution": "log-gaussian",
        # 返回原始尺度便于展示
        "mean_raw": np.mean(feature_values),
        "p99_raw": np.percentile(feature_values, 99),
    }
```

#### （2）错误率类：Beta分布（0-1比例）

```python
def compute_rate_proportion_baseline(feature_values):
    """
    适用：error_rate_4xx等比例特征
    """
    # 比例数据用Beta分布建模更准确
    # 简单起见用均值±2σ近似
    mu = np.mean(feature_values)
    sigma = np.std(feature_values)
    p99 = np.percentile(feature_values, 99)
    
    return {
        "mean": mu,
        "std": sigma,
        "p99": p99,
        "distribution": "beta",
    }
```

#### （3）熵值类：直接高斯

```python
def compute_uri_entropy_baseline(entropy_values):
    """
    适用：uri_entropy等接近正态分布的特征
    """
    mu = np.mean(entropy_values)
    sigma = np.std(entropy_values)
    p50 = np.percentile(entropy_values, 50)
    p99 = np.percentile(entropy_values, 99)
    
    return {
        "mean": mu,
        "std": sigma,
        "p50": p50,
        "p99": p99,
        "distribution": "gaussian",
    }
```

### 4.4 分维度基线

**重要：基线应按业务维度细分，不能让不同流量混在一起**

```python
# 按路径分组的基线
baseline_by_path = {}
for path in unique_paths:
    sub_df = df[df['path_group'] == path]
```

- 不同路径的请求速率天差地别
- 不同租户的流量模式截然不同
- 应用更新后特征分布会漂移

## Step 5：阈值设定

### 5.1 阈值分类

| 阈值类型 | 计算方式 | 用途 |
|---------|---------|------|
| **Z-score阈值** | z=(x-μ)/σ | 高斯分布特征 |
| **分位数阈值** | p99/p99.9 | 分布不明特征 |
| **比例阈值** | 直接设% | 允许一定比例异常 |

### 5.2 Z-score阈值设定

```
基础设定：
  |z| ≥ 2.0 → ALERT (约95%置信区间外)
  |z| ≥ 3.0 → ACTION (约99.7%置信区间外)

经验值（可调）：
  速率类特征：z ≥ 2.0
  熵值类特征：z ≥ 2.5（更宽松，避免误报）
  错误率类：z ≥ 3.0（更严格）
```

### 5.3 用验证集校准阈值

```python
from sklearn.metrics import precision_recall_curve

def calibrate_threshold(val_baseline, val_normal_df, val_attack_df):
    """
    在验证集上用正常数据算误报率，用攻击数据算漏报率，
    找到最优z-score阈值。
    """
    # 1. 计算正常数据的z-score分布
    normal_zscores = []
    for feature, row in val_normal_df.iterrows():
        for fname in FEATURE_LIST:
            z = (row[fname] - val_baseline[fname]['mean']) / val_baseline[fname]['std']
            normal_zscores.append(z)
    
    # 2. 计算攻击数据的z-score分布
    attack_zscores = []
    for feature, row in val_attack_df.iterrows():
        for fname in FEATURE_LIST:
            z = (row[fname] - val_baseline[fname]['mean']) / val_baseline[fname]['std']
            attack_zscores.append(z)
    
    # 3. 尝试不同阈值，评估精确率/召回率
    print("阈值 | 误报率 | 漏报率")
    for threshold in [1.5, 2.0, 2.5, 3.0, 3.5]:
        normal_flag = sum(1 for z in normal_zscores if z >= threshold) / len(normal_zscores)
        attack_flag = sum(1 for z in attack_zscores if z >= threshold) / len(attack_zscores)
        print(f"{threshold:4.1f} | {normal_flag:.3f} | {1-attack_flag:.3f}")
    
    # 4. 选择误报率 < 1% 的最高召回率阈值
```

### 5.4 阈值决策矩阵

```
正常 vs 攻击：如何用多特征综合判断？

单一指标误报高 → 使用"投票/评分"机制

┌────────────┬─────────────────────────────────┐
│ 请求        │ 是否多个特征同时偏离？           │
│ 行为        │                                 │
│            │ request_rate  z=0.5  (正常)      │
│ (单IP)     │ uri_entropy   z=0.8  (正常)      │
│            │ error_4xx     z=1.1  (临界)      │
│            │ ─────────────────────────────   │
│            │ 无特征超过阈值 → 正常             │
│            │                                 │
│ 正常流量：   │ 正常                            │
│            │                                 │
│ 攻击流量：   │ request_rate  z=5.2  (偏离)     │
│ (暴力破解)  │ error_4xx    z=4.1  (偏离)      │
│            │ uri_entropy   z=2.3  (偏离)      │
│            │ ─────────────────────────────   │
│            │ 单IP出现多个特征偏离 → 判为攻击    │
└────────────┴─────────────────────────────────┘

综合评分规则（参考）：
  - 任一特征 z≥3 → 直接标记
  - 两个及以上特征 z≥2 → 标记
  - 单特征 z≥2 → 观察（低置信）
```

### 5.5 动态阈值（进阶）

```
简单阈值 vs 动态阈值：

① 基础阈值（静态z-score）
   z ≥ 2.0 → 告警

② 时段感知阈值
   白天 z ≥ 2.0 | 夜间 z ≥ 3.0
   凌晨流量波动大，需更大阈值避免误报

③ 业务感知阈值
   促销/大促 → 全局放宽
   敏感路径(/login, /admin) → 收紧
```

## Step 6：验证与校准

### 6.1 验证流程

```
① 离线回放验证
   用历史数据回放，检查：
     - 误报率（正常流量判为异常）
     - 漏报率（攻击流量漏判）

② 影子模式验证（关键！）
   旁路并行运行（只记录，不拦截）
     - 对比现有规则/WAF的判定
     - 人工审查高置信告警
     - 持续1-3天收集反馈

③ 小范围灰度
   仅对某IP段/某路径启用
   观察业务是否受影响
```

### 6.2 评估指标

```python
def evaluate_baseline(baseline, normal_df, attack_df):
    """
    评估基线检测性能
    """
    # 记录单IP的z-score最大值
    def max_zscore(row):
        return max(
            abs((row[f] - baseline[f]['mean']) / baseline[f]['std'])
            for f in FEATURE_LIST
        )
    
    # 误报率：正常流量被标记的比例
    normal_flag = sum(
        1 for _, row in normal_df.iterrows()
        if max_zscore(row) >= threshold
    ) / len(normal_df)
    
    # 漏报率：攻击流量未被标记的比例
    attack_flag = sum(
        1 for _, row in attack_df.iterrows()
        if max_zscore(row) >= threshold
    ) / len(attack_df)
    
    detection_rate = attack_flag  # 召回率
    fp_rate = normal_flag         # 误报率
    
    # F1分数（综合评估）
    precision = attack_flag / (attack_flag + normal_flag)
    recall = attack_flag
    f1 = 2 * precision * recall / (precision + recall)
    
    return {
        "false_positive_rate": fp_rate,
        "detection_rate": detection_rate,
        "precision": precision,
        "f1_score": f1,
    }
```

## Step 7：动态更新

### 7.1 为什么需要更新（概念漂移）

```
应用是动态的：
  - 新功能上线 → 新路径、新参数
  - 用户增长 → 流量整体上涨
  - 季节波动 → 节假日峰值
  - 架构调整 → 响应时间变化

基线若不更新 → 漂移 → 大量误报
```

### 7.2 滚动窗口更新

```
滚动窗口法（推荐）：

使用最近N天的数据维护基线，滑动前进：

  ┌─────────────────────────────────────────────┐
  │ 第1天 第2天 ... 第6天 第7天                     │ ← 窗口1
  └─────────────────────────────────────────────┘
                    ┌────────────────────────────2─┐
                    │ 第2天 ... 第7天 第8天           │ ← 窗口2
                    └──────────────────────────────┘
                          ┌──────────────────────────3┐
                          │ 第3天 ... 第8天 第9天       │ ← 窗口3
                          └────────────────────────────┘
  每次前进1天，总是用最近7天数据
```

### 7.3 事件触发更新

```
除定时更新外，以下事件应触发基线重算：

  ✅ 正常事件（应更新）：
    - 新功能上线
    - 重要活动/促销
    - 用户量显著变化

  ❌ 攻击事件（不应更新）：
    - 检测到攻击（不能把攻击学进基线！）
    - 异常高峰（可能是DDoS）

  实现：基线更新时排除"已标记为异常"的时间段
```

### 7.4 增量更新公式（无需全量重算）

```python
def incremental_update(old_mu, old_sigma, old_n, new_values):
    """
    增量更新均值与标准差，避免每次全量重算。
    使用Welford在线算法。
    """
    count = old_n
    mean = old_mu
    M2 = (old_sigma ** 2) * old_n  # 二阶矩
    
    for x in new_values:
        count += 1
        delta = x - mean
        mean += delta / count
        delta2 = x - mean
        M2 += delta * delta2
    
    variance = M2 / count
    std = variance ** 0.5
    
    return {"mean": mean, "std": std, "n": count}
```

### 7.5 漂移检测

```
用PSI（Population Stability Index）检测特征分布是否漂移：

PSI = Σ (p_current_i - p_baseline_i) × ln(p_current_i / p_baseline_i)

判断：
  PSI < 0.1  → 无明显漂移
  0.1 ≤ PSI < 0.25 → 轻度漂移（观察）
  PSI ≥ 0.25 → 显著漂移（立即重算基线）
```

```python
def psi_score(expected, actual, bins=10):
    """
    计算当前分布 vs 基线分布的分段偏移
    """
    # 分箱
    hist_exp, _ = np.histogram(expected, bins=bins)
    hist_act, edges = np.histogram(actual, bins=bins, range=edges_range)
    
    # 转比例
    p_exp = hist_exp / np.sum(hist_exp) + 1e-6  # 防除零
    p_act = hist_act / np.sum(hist_act) + 1e-6
    
    # PSI
    psi = np.sum((p_act - p_exp) * np.log(p_act / p_exp))
    return psi
```

### 8.2 在线检测实现

```python
def detect_anomaly(ip, current_features, baseline):
    """
    实时检测单个IP是否异常
    """
    scores = {}
    for fname, value in current_features.items():
        if fname not in baseline:
            continue
        bl = baseline[fname]
        
        # 计算z-score（注意：速率类用log变换后的基线）
        if bl['distribution'] == 'log-gaussian':
            value = np.log1p(value)
            z = (value - bl['mean']) / bl['std']
        else:
            z = (value - bl['mean']) / bl['std']
        
        scores[fname] = z
    
    # 综合判定
    max_z = max(abs(z) for z in scores.values())
    high_scores = [f for f, z in scores.items() if abs(z) >= 2.0]
    
    if max_z >= 3.0 or len(high_scores) >= 2:
        return "BLOCK", scores
    elif max_z >= 2.0:
        return "ALERT", scores
    else:
        return "NORMAL", scores
```

## 进阶：多维基线

### 在实战中，单一全局基线往往不够

#### 1. 按路径维度

```
不同路径流量模式差异巨大：

  /api/login    → 高频率，突发性强
  /order/detail → 低频，但重要
  /static/*     → 超高频率，静态资源
  
应该为每个路径组建立独立基线
```

#### 2. 按用户维度

```
按用户级别区分：
  - 匿名用户 → 宽松基线（易误报）
  - 登录用户 → 严格基线
  - VIP用户 → 极严格
```

#### 3. 按时间维度

```
时段基线（关键）：
  ├─ 工作日 vs 周末
  ├─ 高峰时段 vs 低谷时段
  └─ 节日活动期

示例：
  /api/login 工作日晚8点峰值 300/min
           凌晨3点基线 10/min
           → 凌晨30/min 已经异常！
```

#### 4. 多维度综合（建议）

```
推荐结构：按「路径组 × 时段」建立基线
```

## 常见问题与坑

### 问题1：冷启动（没有历史数据）
- **表现**：新应用无法立即建基线
- **对策**：
  - 用滚动7天在线学习，而非等待7天
  - 先用宽松阈值（z=3.0），逐步收紧
  - 借同类应用的经验基线做初始值

### 问题2：基线被攻击污染
- **表现**：学习期被攻击注入，把恶意当正常
- **对策**：
  - 学习期结合签名规则过滤明显攻击
  - 剔除异常时间段的样本
  - 使用稳健统计（中位数/MAD取代均值/标准差）

### 问题3：分布非高斯
- **表现**：直接套σ导致误报
- **对策**：
  - 先做分布检查（偏度/峰度）
  - 对数/Box-Cox变换
  - 改用分位数(p99)而非σ

### 问题4：大促/活动误报
- **表现**：正常大促流量被判为攻击
- **对策**：
  - 基线更新排除特殊事件
  - 支持设置"活动模式"豁免窗口
  - 用业务日历预判流量突增

### 问题5：慢速攻击漏报
- **表现**：低慢速攻击（低频、持久）无法触发阈值
- **对策**：
  - 拉长时间窗口检测累计行为
  - 使用LSTM/序列模型补充
  - 结合蜜罐/诱饵检测

### 问题6：单一IP vs 分布式攻击
- **表现**：分布式攻击每个IP都很小，检测不到
- **对策**：
  - 增加"路径+UA"聚合维度
  - 检测同UA跨IP的异常模式
  - 全局速率与单IP速率结合
